## Key Architectural Concepts

### 1. Session Protection System
**Location:** `App.jsx:62-66`

Prevents automatic project updates from clearing chat during active conversations:

```javascript
const [activeSessions, setActiveSessions] = useState(new Set());

markSessionAsActive(sessionId);      // Pause updates
markSessionAsInactive(sessionId);    // Resume updates
```

**When modifying**: Always consider impact on session protection logic.

### 2. Project Discovery
**Location:** `server/projects.js:1-58`

- **Claude**: `~/.claude/projects/` with encoded paths
- **Cursor**: `~/.cursor/chats/{md5}/` - MD5 hash of project path
- **Limitation**: Cannot auto-discover Cursor-only projects

### 3. Dual WebSocket Endpoints
**Location:** `server/index.js:520-536`

- `/ws` - Chat and project updates
- `/shell` - Terminal emulation (PTY)

### 4. JSONL Session Storage
**Location:** `server/projects.js:649-710`

Sessions stored as JSON Lines (JSONL), not JSON arrays. Parse line by line.

## Common Gotchas

### 1. Session Protection
When adding features that update projects/sessions, ALWAYS check:
```javascript
// App.jsx - Check if session is active before updating
const hasActiveSession = activeSessions.has(selectedSession.id);
if (hasActiveSession) {
  // Skip or defer update
}
```

### 2. ChatInterface Complexity
`ChatInterface.jsx` is 3484 lines. When modifying:
- Extract logic into smaller components
- Use hooks for reusable state
- Consider creating sub-components

### 3. Native Modules
Three native modules require compilation:
- `node-pty` - Terminal emulation
- `better-sqlite3` - Database
- `bcrypt` - Password hashing

Requires Python + C++ build tools.

### 4. WebSocket Authentication
Always include token in WebSocket URL:
```javascript
const wsUrl = `ws://host:port/ws?token=${encodeURIComponent(token)}`;
```

### 5. Mobile Responsiveness
Always test mobile layout:
- Use `isMobile` prop
- Check bottom navigation
- Test touch gestures
- Verify PWA mode
